- [x] **修复：视频播完自动续播时未真正自动播放（仅切换预览、停在暂停态）** — 这是 #33「视频播放完自动播放下一个」的**回归/未真正接上**项。现状：`VideoPreview.vue:onEnded`（line 291）已正确算出下一个视频并发 `emit("open-next", {...})`；`App.vue:playNextVideo`（line 439）也正确把 `previewFilePath/Name/Bytes` 换成下一个，触发 `VideoPreview` 的 `watch(() => props.filePath)`（line 558）→ 调 `loadVideo()`。但 `loadVideo()`（line 526）只重设 `videoSrc = convertFileSrc(props.filePath)` 并 `playing.value = false`，**从不调用 `videoEl.value.play()`**，且没有 `autoplay` 属性，于是新视频加载完成却停在暂停帧（中央显示 ▶ 大播放钮），与用户反馈「预览展示的是下一条，但是并没有自动播放」完全吻合。目标：自动续播时应真正开始播放下一个。需处理：① 区分「自动续播」与「用户手动打开/↑↓切换」——后者应保持暂停态让用户点 ▶（现有行为）；② 实现：新增 `pendingAutoplay` ref，`onEnded` 在 `emit("open-next")` 前设 `pendingAutoplay = true`；`loadVideo()` 入参 `autostart` 或在 `onLoadedMetadata`（line 269）里判断 `pendingAutoplay`——新 `src` 异步加载完成才 fire metadata，此时 `videoEl.value.play().catch(()=>{})` 并清 `pendingAutoplay`；③ 注意 `loadVideo` 先 `videoSrc.value = ""` 再赋新值，watch 触发时机要等真实 onLoadedMetadata；④ 浏览器自动播放策略可能拦截带声播放（用户已在本会话点过播放通常放行），被拒则静默停在暂停态即可；⑤ 仅 `VideoPreview.vue` 改动，纯前端，待用户双击 `dev.bat` 实测。
  - 实现：`VideoPreview.vue` 新增 `pendingAutoplay` ref；`onEnded` 在 `emit("open-next")` 前设 `true`；`onLoadedMetadata` 检测到则 `videoEl.value.play().catch(()=>{})` 并清旗；`onError` 也清旗防泄漏。另补「文件列表选中跟随」：`FileList.vue` 新增 `selectName(name)`（按名单选+滚动），经 `FilePanel.vue` 的 `defineExpose` 转暴露；`App.vue:playNextVideo` 在换预览前把来源面板（previewPanel 的对侧）的选中项移到 `payload.name`。改完前端未跑构建，待用户双击 `dev.bat` 实测。
  - 续改（用户要求「视频顺序与列表一致、优先数字、不要自己排序」）：`VideoPreview.onEnded` 不再 `listDirectory` 后字典序重排目录，改为只 `emit("open-next", { name: 当前文件名 })`；`FileList.vue` 新增 `getNextVideoEntry(name)`（在 `displayedEntries` 当前顺序里找下一个视频、跳过非视频与目录），经 `FilePanel.vue` 暴露；`App.vue:playNextVideo` 据来源面板 `getNextVideoEntry(当前名)` 解析下一视频并换预览+选中。因 `sortedEntries` 已用 `localeCompare(...,{numeric:true})` 自然排序，列表本身即 `爱莉希雅 (1)→(2)→…→(10)`，视频顺序据此自动一致；且若用户按 size/modified 排序，视频续播也跟随该顺序。纯前端，待用户双击 `dev.bat` 实测。
