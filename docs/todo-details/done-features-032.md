- [x] **修复：按空格统计的目录大小在窗口失焦再回来后丢失** — 用户实测：对目录按 `Space`（`list.dirSize` → `getDirSize`）统计出占用空间并显示在 Size 列后，**切到别的程序再切回 mini-tc，统计结果被清空变回空白**，必须重新按一次空格。期望：**只要没切换目录**，目录大小就该保留，失焦/回来、被动 `refresh()` 都不能丢。根因：`FilePanel.vue:953` 在 `loadDirectory` 的 `if (isActive && !silent)` 分支里无条件 `dirSizes.value = {}`，而 `refresh()`（`FilePanel.vue:1063`，由 `App.vue` 的 `tauri://focus` 触发）调用 `loadDirectory(activeTab.value.path, id)` **没有传 `silent`** → 每次切回窗口都走清空分支。注意 `dirSizes` 的 key 是 `dirKey(entry)`（普通目录用 `entry.name`，搜索结果 tab 用 `entry.path`），同目录重列后 key 不变，所以只要不清空就能直接复用。需处理：① 清空条件从「非静默加载」改为「**目录真的变了**」（比较 `path !== 上次加载的 path`，或按 tab 分桶 `dirSizesByTab[tabId]`），被动 refresh 同目录重列时保留；② 明确失效时机——切换目录（含面包屑/前进后退/书签/`navigateParent`）、切换 tab、删除目录（现有 `onDelete` 已按 name/path 剔除，保留）、目标目录被外部删除后可考虑丢弃；③ 与 `silent` 的职责边界理顺：`silent` 控制的是「Loading 闪不闪 / 清不清选中」，`dirSizes` 保留与否应独立判断，别再借 `silent` 顺带决定；④ 可选：切回窗口时目录内容可能已变，是否需要失效策略（如超时节流内保留 / 强制 ↻ 才重算）——按用户「除非切换目录」的口径，默认保留即可，不要自作主张加自动重算（重算大目录很贵）。
  - 实现（纯前端，零后端改动）：`dirSizes` 从「整面板一张平面 map」改为 **`dirSizesByTab[tabId] = { path, sizes }` 按标签页分桶**。分桶解决两件事：① 平面 map 会被 `loadDirectory` 里「真导航」与「被动 refresh」共用的那条分支清空（`refresh()` 不传 `silent` → 每切一次窗口丢一批）；② 同名目录的大小不会跨标签页串台。
  - **失效点定在 `setPath()`**（**所有目录切换的唯一收口**：面包屑、`navigateParent`、`stepHistory` 前进后退、书签、锁定跳转、搜索结果下钻全走它，连 `record:false` 的历史移动也走）——切目录即 `dropDirSizes(tab.id)`。**⚠️ 口径按用户实测反馈收紧**：最初实现只在 `computed` 里做「path 戳对不上就返回空」，用户指出「切走再切回来数字又活了」不对——**戳在切回来那一刻又对上了**。用户口径是「**切换目录就应该清空**」，理由成立：这些数字是某一时刻的快照，走一圈回来期间完全可能在别处增删过里面的文件，**一本正经地显示一个错的数字比留空更糟**（留空至少会让人再按一次空格）。故改为在切换的那一刻就丢桶；path 戳降级为纯防御（万一将来有人绕过 `setPath` 直接写 `tab.path`，不会复活别的目录的数字）。
  - 明确**不属于「切换目录」因而不清空**的：窗口失焦回来触发的 `refresh()`、点 ↻ 强制刷新、粘贴/解压/重命名后的 `refresh()` —— 它们都只是**重新列一遍当前这个目录**，不经过 `setPath`，故数字保留（这正是本次要修的 bug 本身）。删除目录时（`onDelete`）剔除对应条目，避免同目录重新列出时已删文件夹的尺寸「诈尸」；`closeTab` 一并清桶，否则会随窗口生命周期一直占内存。
  - 顺带修两处**新机制暴露出来 / 紧邻的既有 bug**：① `calcDirSize` 在第一次 `await` 之前就固定 `(tabId, path)`，`getDirSize` 回来后先核对 tab 与路径仍一致，不一致就**丢弃**结果——大目录统计要跑几秒，原实现会让晚到的结果写到当时正在显示的另一个目录头上；② `FileList.vue` 的 `v-if="!== undefined"` 排在 `v-else-if="=== -1"` 前面，导致 `...`（计算中）这个分支**永远不可达**，计算中的目录实际显示成 `NaN undefined`（`formatSize(-1)` 里 `Math.log(-1)` = NaN）。已把 `-1` 的判断提到前面。
  - `vite build` exit 0（主 bundle 240.82 kB，与改动前 238.39 kB 基本持平；纯前端未跑 cargo）。待用户双击 `dev.bat` 实测，重点：① 选中一大目录按空格算完，切到别的程序再切回，Size 列**仍是原来的数字**；② **导航到别的目录 → 数字消失；用 Backspace / `Alt+←` 切回来 → 仍是空的**（不回弹）；③ 左栏算过的 `Documents` 不影响右栏同名的 `Documents`；④ 统计一个超大目录，中途立刻导航走，事后原目录不出现莫名其妙的尺寸；⑤ 算完就删掉该文件夹，列表里不残留尺寸。
