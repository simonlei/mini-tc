- [x] **批量重命名工具（Ctrl+M）** — 选中多个文件/文件夹后弹出重命名面板：左侧当前名、右侧实时预览新名（非法名 / 重名标红），支持模式：查找替换（区分大小写 / 正则）、序号占位（`[N]` 起始值 / 步长 / 位数）、前后缀插入、大小写转换、替换扩展名。需处理：① 复用已有 `renameFile(oldPath, newName)`（`api.js:65`），纯前端实现、后端零改动；② 顺序问题——必须先「全部算出新名」再「逐个执行」，并检测新名集合内重名冲突；③ 环形冲突（`a→b` 且 `b→a`）需两阶段改名（先临时名再目标名）；④ 部分失败要能回滚或明确列出失败项，不要让列表停在半改名状态；⑤ 与 F2 内联改名、模糊搜索过滤态（`displayedEntries`）、多选集合共存；⑥ 快捷键进 `shortcuts.js`，面板做成可复用对话框（参考 `SettingsDialog.vue` / `ShortcutsDialog.vue` 的遮罩弹窗风格）。
  - 实现（纯前端 + 后端零改动，三层拆分）：**① `src/renameRules.js`（纯函数，可单测）** —— `splitName`（主名/扩展名分离，`.gitignore` 视为主名无扩展名）、`validateName`（Windows 非法字符 / C0 控制符 / 结尾点空格 / `CON`·`NUL`·`COM1-9`·`LPT1-9` 保留设备名 / 255 字符上限）、`computeNewName`（六段流水线：查找替换 → `[N]` 占位符 → 大小写 → 自动追加序号 → 前后缀 → 扩展名）、`buildRenamePlan`（产出 `ok`/`unchanged`/`error` 三态行）、`planPhases`（两阶段排程）。**关键设计**：① **主名与扩展名分开处理** —— 查找替换/大小写/序号只作用于主名，扩展名单独一节，否则「查找 `.` 换 `_`」这种规则会毁掉扩展名；② **冲突检测按目录分组**，绝不全局判重 —— 搜索结果伪目录的行来自不同文件夹，两个同名目标完全合法；③ **所有名字比较一律忽略大小写**（Windows 文件系统就是如此，`a→B` 与 `c→b` 是真冲突，大小写敏感的检查会放过去然后被 OS 拒绝）；④ **「本批腾出的名字」不算冲突**（`a→b, b→a` 合法，交给 `planPhases`），但「别人不走、你要占」是冲突。**② `src/renameRunner.js`（执行器，无 IO 依赖）** —— `move(fromPath, toName)` 以参数注入，故可在纯 node 下对着内存文件系统跑（`scripts/rename-rules-check.mjs`，**102 条断言**）。执行顺序是 **1a 暂存环形项 → 2 就地改无冲突项 → 1b 临时名→终名**：⚠️ **phase 2 必须在 1b 之前**，链式改名（`a→c` + `b→a`）里 `b→a` 进 phase 1 的原因正是「此刻 `a` 还占着」，而**腾出 `a` 的正是 phase 2 的 `a→c`** —— 写反了会报「目标已存在」，看起来像权限问题实为顺序 bug（此坑由测试实际踩出并修正）。任一步失败即**逆序回滚全部已完成的改动**，回滚本身失败则如实列出残留路径而非假装干净；临时名 `~minitc_tmp_<rand>_<i>` 会主动避开目录中已有名字。**③ `src/components/BatchRenameDialog.vue`** —— 左侧规则表单（分组 section）+ 右侧逐行「当前名 → 新名」实时预览，错误行标红并划掉新名 + 行内给出原因（非法字符 / 与本批次其他项重名 / 目标已存在同名项），底部实时统计「将重命名 N 项 · M 项不变 · K 项有误」，**有任一错误则「重命名」按钮禁用**（不靠 toast 事后提醒）。Esc 在 capture 阶段拦截（压过 App.vue 的「Esc 关预览」）。**④ 接入** —— `shortcuts.js` 注册 `list.batchRename`（scope `global`，默认 `Ctrl+M`；不用 `fileList` 是因为对话框由 App.vue 挂载、需要面板的绝对路径而非列表下标，且与 F5/Ctrl+T 同理无 webview 原生语义）；右键菜单加「批量重命名…」→ emit `batch-rename` 事件（对话框要盖在**两个面板之上**并独占键盘，故不能放在 FilePanel 内部），`onPanelBatchRename` 先把该面板设为活动栏，保证对话框 / 事后刷新 / 焦点还原三者指向同一侧。**⑤ 搜索结果 tab 的显示刷新是面板的知识，不在前端猜** —— 真实目录 `refresh()` 重列即可，但伪目录的 `refresh()` **刻意是 no-op**（被动刷新绝不能偷偷全盘重扫，详见 `FilePanel.refresh`），所以新增 `FilePanel.applyRenames(pairs)`：按 tab 类型决定「重列」还是「就地改行」（与单条 `onRename` 同一套手法）。**⑥ 模态纪律**（沿用搜索对话框的教训）—— 打开时记 `activeElement` + 所属面板、关闭时 `nextTick` 精确还原；App.vue 全局 keydown 开头 `if (batchRenameVisible) return`，否则在规则输入框里敲 `Backspace` 会让背后面板返回上级目录。
  - 验证：`vite build` exit 0（主 bundle 257.26 kB，改动前 256.90 kB）；`scripts/rename-rules-check.mjs` **102 passed / 0 failed**（覆盖 `splitName` 边界、`validateName` 各分支含 `console` 非保留而 `com10` 是、替换的大小写与正则捕获组、序号起始/步长/位数/占位符、四种大小写转换、扩展名四态、同目录重名 vs 跨目录同名合法、`planPhases` 的纯互换与链式分批、以及执行器的简单批 / 互换 / 链式 / 中途失败回滚 / **失败发生在 1b 阶段时临时名也不残留** / 回滚自身失败如实上报 / 有 error 行时零 IO）。后端未跑 cargo（零改动）。待用户双击 `dev.bat` 实测。
