- [x] **递归文件搜索（Ctrl+F，TC 习惯 Alt+F7）** — 当前 `/` 只对**当前目录**做文件名模糊过滤，没有递归搜索，这是最大的操作能力缺口。目标：新开搜索面板，在指定根目录下按文件名（glob / 子串 / 正则）递归查找，可选按内容 grep、按大小 / 修改时间 / 扩展名过滤。需处理：① 后端新增命令（如 `search_files(root, pattern, options)`）——递归时跳过无权限目录、尊重隐藏文件开关，结果**分批 / 流式**回传（事件或分页），避免大目录卡死界面；② 可取消：在独立线程（tauri async / `std::thread`）跑并支持 cancel 标志（本条先做最小版，后续可并入「后台任务队列」通用化）；③ 内容 grep 需先按扩展名 + 二进制嗅探（读前若干字节判 NUL）过滤，避免扫大二进制文件；④ 结果列表需虚拟滚动（可能上万条），回车跳转到所在目录并选中该文件（可复用 `FileList.vue` 已暴露的 `selectName(name)`）；⑤ 结果项支持复制路径 / 删除 / 预览，复用现有右键菜单；⑥ 入口为菜单项 + 快捷键，`shortcuts.js` 注册时注意 `Ctrl+F` 与浏览器 / 预览区内查找的冲突，建议 scope 限定 `fileList`；⑦ 与现有 `/` 即时过滤的定位区分：前者重量级递归、后者当前目录轻量过滤，两者并存。
  - 实现（后端 `src-tauri/src/lib.rs`，**零新增依赖**）：新增 `start_search(app, id, options)` / `cancel_search`。`start_search` 只校验根目录并 `std::thread::spawn` 后台线程后**立即返回**，结果经 `search-batch`（每 200 条或 200ms 一批）流式 emit，结束发 `search-done`（scanned / matched / cancelled / truncated / errors）。新搜索自动取消上一次（全局 `SEARCH_CANCEL` 存 `Arc<AtomicBool>`），每批带 `id`，前端据此丢弃过期扫描的残留事件。遍历用**显式栈 DFS**（不入递归，深度上限 64），每个目录内条目按名称排序、子目录**逆序压栈**→ 结果天然按「目录 + 名称」顺序流出；**跳过符号链接目录**防环；`read_dir` 失败计入 errors（最多 5 条）而非中断。匹配：`;` 分隔多模式，含 `*`/`?` 走自实现的 `glob_match`（双指针 + `*` 回溯），否则按子串；大小写开关统一处理。内容 grep 仅在「包含内容」非空时执行：跳过 0 字节 / >8MB / 前 4KB 含 NUL（二进制嗅探）的文件，其余整读后 `from_utf8_lossy` 再 contains。结果上限 5000（后端 clamp 到 50000）。
  - 实现（前端）：新增 `src/components/SearchDialog.vue` —— 搜索目录 / 文件名 / 包含内容 / 区分大小写 / 包含隐藏文件 + 搜索·停止；虚拟滚动结果列表（固定行高 24px，只渲染可视窗口，ResizeObserver 跟随高度）；双击 / 回车 / 方向键 + Enter 跳转，右键菜单（跳转到该文件 / 打开所在目录 / 复制完整路径 / 用系统默认程序打开）；状态栏显示已扫描数 / 命中数 / 用时 / 取消 / 截断 / 扫描错误；Esc 关闭（capture 阶段拦截，避免误触 App.vue 的「Esc 关预览」）；关闭时若搜索仍在跑则自动 `cancelSearch`。`api.js` 加 `startSearch` / `cancelSearch`。
  - 接入：`shortcuts.js` 注册 `search.open`（scope `global`，默认 `Alt+F7` + `Ctrl+F`）；`App.vue` 菜单栏新增「搜索」项 + keydown 处理（搜索框已打开时不重复触发）、`onSearchReveal` / `onSearchOpenDir` / `onSearchUseCurrentDir` —— 跳转前若活动面板正在显示预览则先 `closePreview`；`FilePanel.vue` 的 `defineExpose` 新增 `revealFile(dir, name)`（同目录走 `selectName`，跨目录挂 `pendingSelectName` 由 FileList 在列表落地时选中）与 `goTo(path)`。大小 / 修改时间 / 扩展名过滤本轮未做（TODO 原文标为可选）。vite build exit 0，`cargo check` + `cargo fmt --check` 均 exit 0，待用户双击 `dev.bat` 实测。
  - **修复（实测后的性能 bug）**：用户反馈「在没有子目录的目录下搜 `*.mp4` 很久不返回」。根因不是死循环，而是遍历里对每个条目调了 `fs::metadata(&path)`——Windows 上这会重新解析并打开一次文件，而 TC 快是因为直接用 `FindFirstFile` 已返回的属性。独立基准（rustc 裸编译，无 Tauri 依赖）实测：`C://Windows//System32` 4 782 项 → 只读目录 1.6 ms、`fs::metadata(path)` **373 ms（冷）/ 78 ms（热）**、`entry.metadata()` **1.3 ms**；`C://Program Files` 递归 51 100 项 → **1.89 s vs 0.22 s（快 8.6 倍）**。改动：① `entry.metadata()` 取代 `fs::metadata(&path)`（仅在 DirEntry 数据缺失时回退，Windows 上零额外 syscall）；② 延迟构造 `entry.path()`，只在命中 / 子目录入栈时才 `PathBuf` 分配；③ 排序改 `sort_by_cached_key`（每个名字只小写化一次，而非每次比较都分配）；④ 新增 `search-progress` 事件（约每 300 ms，带 scanned / matched / 当前目录），前端状态栏实时显示「正在扫描：…\末两段」——原实现在扫大目录且无命中时**一个事件都不发**，界面「已扫描 0 项」直到结束，看起来就是卡死；⑤ 取消标志改为**每个条目**都查（原子 load 只要几 ns），只对读时钟做 mask 节流——原实现挂在 `scanned % 256`，目录内不足 256 项时停止按钮完全无效。注意后端已有同名 `emit_progress`（复制进度用），新的改名 `emit_search_progress`。
  - **同一根因顺带修了 `list_directory`**：列目录原先用 `fs::metadata(&file_path)` 取属性，且 `is_hidden(name, path)` 内部**又**调一次 `fs::metadata` 判隐藏位 —— 每个条目 **2 次**额外系统调用，是比搜索更高频的路径（每次打开目录 / 切标签都在付）。现改为 `entry.metadata()`（仅 symlink 为保持「跟随目标」语义才回退 `fs::metadata`），`is_hidden` 签名改为收 `&Metadata` 复用已有结果；同时删掉搜索里重复的 `is_entry_hidden`，统一用 `is_hidden`。
  - **真正的病根（第二轮，用户用 4 文件的 `src-tauri/gen/schemas` 复现）**：与性能无关。`@tauri-apps/api` v2 的 `listen` 回调收到的是 **`Event` 包装对象** `{ event, id, payload }`，不是 payload 本身——`Event.id` 是全局递增的**事件序号**，与 payload 里的搜索任务 id 毫无关系。`SearchDialog.vue` 三个 handler 全写成了直接收 payload，于是 `payload.id !== searchId` 恒成立 → **每个事件都被丢弃**，`hits` 永远空、`search-done` 永远收不到、`searching` 永远为 true（表现为「很久出不来」）。项目里 `App.vue` 的 `copy-progress` / `drag-*` 写法正确（`event.payload`），所以只有搜索这一处出错。
  - **加固措施**：① 三个 handler 统一走 `unwrap(event, name)` 辅助函数解包 `.payload`，异常形状 `console.warn`；② 新增 `src-tauri/src/search_log.rs`——GUI 程序在 Windows 上无控制台，`eprintln!` 等于丢弃，故把入口参数 / 每个进入的目录 / 每个命中 / **每种事件的 `emit` 返回值**（此前全被 `let _ =` 吞掉，emit 失败与「没结果」无法区分）/ `read_dir` 失败 / 汇总行写入 `%USERPROFILE%\.minitc\logs\search.log`，每次搜索覆盖；③ `install_panic_hook()` 用 `Once` 装全局 hook（链式调用原 hook）把 panic 信息写进同一文件；④ 搜索线程包 `catch_unwind(AssertUnwindSafe(..))`，panic 也发一条 `search-done`，线程结束用 `Arc::ptr_eq` 认领式清空 `SEARCH_CANCEL`；⑤ 前端「停止」后 1.5 s 兜底定时器，若仍无 `search-done` 就本地收尾并提示看日志——保证任何情况下都不会卡死；⑥ 对话框底部「诊断日志」可点开显示日志路径。
  - **搜索框的模态行为（用户反馈：Esc 关闭后焦点没回文件列表）**：`@close="searchVisible = false"` 只翻了个 ref，键盘就停在 `<body>` 上，什么键都无效。改为 `openSearch` 记下 `searchReturnPanel` + `document.activeElement`，`closeSearch` 在 `nextTick` 里**精确还原**那个元素（文件列表 / 地址栏 / 文件名过滤框），元素已从 DOM 移除或焦点无处可还时才回退 `panel.focusList()`；`onSearchReveal` / `onSearchOpenDir` 跳转后也补上 `focusList()`。同时发现**同源的按键穿透**：全局 keydown 绑在 `document` 上，搜索框里敲的键会冒泡上去，除了 `search.open` 有一道 `if (searchVisible.value) return` 之外，**其余快捷键全部照常触发**——在文件名框按 `Backspace` 会让背后面板返回上级目录、`Delete` 会删文件、方向键会移动背后光标。已在全局 handler 开头加 `if (searchVisible.value) return;`。⚠️ 只对搜索这么做：`SettingsDialog` / `GeneralSettingsDialog` 没有自己的 Esc 处理，加通用模态拦截会破坏它们的关闭行为。
