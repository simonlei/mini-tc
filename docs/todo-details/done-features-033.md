- [x] **可执行文件右键菜单增加「以管理员身份运行」** — 当前右键菜单只对压缩包提供外部工具调用（见「右键菜单调用 7-Zip 等外部压缩工具解压」），对 `.exe` / `.bat` / `.cmd` / `.msi` / `.lnk`(指向可执行文件) 这类可执行目标没有任何入口。Windows 资源管理器原生右键就有「以管理员身份运行」（UAC 提权），mini-tc 缺这一项导致删/改受保护位置、或需要装驱动/写注册表时必须切回 Explorer。目标：右键选中可执行文件时追加「以管理员身份运行」菜单项，点击弹 UAC 提权启动。
  - 需处理：① **可执行目标判定** —— 不能只看扩展名：`.exe`/`.bat`/`.cmd`/`.com`/`.ps1`(策略允许时)/`.msi`/`.msp`/`.lnk` 算，`.txt` 关联了某 exe 也可能被要求「用XX打开」；建议后端提供 `is_executable(path)`（读 PE 头 `MZ`+`PE\0\0` 判真 EXE，`.bat/.cmd` 看首行有无可执行命令，其余扩展名交给可配置列表），避免前端堆一个易过期的白名单；② **提权启动实现** —— 参考已有 `delete_with_admin`（`ShellExecuteW` + `runas` 动词）的做法，后端新增 `run_as_admin(path)`，Windows 用 `ShellExecuteW(NULL, L"runas", path, params, workdir, SW_SHOWNORMAL)`，`ShellExecuteExW` 才能取 `hProcess` 做等待/退出码；用户拒 UAC 返回 `ERROR_CANCELLED`(1223) 要 toast「已取消」而不是报错；③ **参数与工作目录** —— 对 `.bat/.cmd` 不能直接把脚本当 exe 跑，需包一层 `cmd.exe /c ""<path>""`（注意 `runas` 下引号转义，`cmd /c` 的双引号嵌套坑）；带空格的路径必须整体引号包住，工作目录取该文件所在目录（不少 exe 依赖 cwd 找同目录资源）；④ **跨平台降级** —— 非 Windows 无 UAC 概念，该菜单项直接不显示（`get_archive_tools` 那套平台探测思路可复用）；⑤ **与既有右键菜单的整合** —— 当前 `ContextMenu.vue` 的菜单项在 `FilePanel.vue` 按 entry 类型拼装，可执行项要插在「打开」附近；⚠️ 拖放/剪切态(`is-cut`)下应禁用（对将被移动的文件提权启动语义混乱）；⑥ UAC 会弹出模态 consent 窗口，此时 mini-tc 窗口失焦属正常，但**若提权目标是我们自己（如以管理员重启 mini-tc）需明确走「重启应用」而非「运行文件」**；⑦ 可选：加「以管理员身份复制/打开所在目录」等衍生项，或记住用户上次选择（如 Shift+点击 直接提权打开）——但**别加「始终以管理员运行」的默认值**，那是用户的显式决定，不是可猜的偏好。
  - ⚠️ 与本项目已有提权设施的复用点：`delete_with_admin` 已封装 `ShellExecuteW` + `runas` + 错误码 1223 识别（见「删除失败时让用户选择是否提权重试」一条），本条应抽出共用函数而非复制粘贴一份。
  - 实现（后端 `src-tauri/src/lib.rs`）：**先把 `delete_with_admin` 里那段 `ShellExecuteW` + `runas` + `HINSTANCE<=32` + 1223 识别抽成共用 `shell_execute_elevated(file, params, work_dir, show_cmd)`**，`delete_with_admin` 改为调用它（行为不变，仍 SW_HIDE + 无工作目录），新增 `run_as_admin` 也走它——UAC 那套管道只写一份。错误文案统一为常量 `ELEVATION_CANCELLED = "已取消管理员权限请求"`，前端一个子串判断就能把「用户主动拒绝」和「真失败」分开。
    - 新增 `is_executable(path) -> bool` 与内部 `executable_kind() -> Option<ExeKind>`，分派 `Direct`/`CmdScript`/`PowerShell`/`Msi`/`Msp`。**判定按内容而非只看扩展名**：`.exe/.com/.scr/.pif` 要 `has_pe_header()` 通过——先验 `MZ`，再按 0x3C 处的 `e_lfanew` seek 到 `PE\0\0`，且对 `pe_off` 做 `0x40..=1MB` 的越界钳制（否则一个伪造的 `e_lfanew` 会把 seek 甩到文件外）；`.bat/.cmd/.ps1/.psm1/.psd1` 要 `script_has_command()` 真有可执行命令行（跳过空行 / `rem` / `::` / 前导 `@`，UTF-16 BOM 会先解码）；`.lnk/.msi/.msp` 按扩展名放行（shell 自己解析快捷方式，msiexec 才有意义）。**刻意不查注册表文件关联**——TODO 原文把「关联了 exe 的 .txt」列为风险，但那要求按扩展名问注册表 `runas` 动词，会让所有文档类型都冒出这个入口，是昂贵且令人意外的查找，改为「扩展名白名单 + 便宜内容嗅探」并在注释里写清理由。
    - `run_as_admin` 按 `ExeKind` 分派：`.bat/.cmd` → `cmd.exe /c "<path>"`（整条命令再包一层引号，含空格才是单个参数）；`.ps1` → `powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "& '<escaped>'"`（单引号转义）；`.msi/.msp` → `msiexec.exe /i|/p`；其余直接启动。**工作目录统一传文件所在目录**（`p.parent()`），`delete_with_admin` 保持传 `None` 不变。命令在提权进程起来后立即返回，不等待，故前端无需刷新。
  - 实现（前端）：`api.js` 加 `isExecutable(path)` / `runAsAdmin(path)`。`FilePanel.vue` 新增 `ctxIsExecutable` ref（**独立于 `ctxEntry`**：可执行性来自文件内容而非列表行，不能让行本身看起来不一样），在 `onCtxMenu`（已 async）里右键命中非目录项时 `await entryPath` + `await isExecutable(full)` 再建菜单，解析失败只 `console.warn` 并**不显示该入口**（宁可没有，也不要一个点了必失败的菜单）。`buildMenuItems` 把「以管理员身份运行」插在「打开」之后，仅在 `ctxIsExecutable` 为真时出现；`disabled: isEntryCut(entry)`——新增的 `isEntryCut` 与 `FileList.vue` 的 `isCut` 同口径（名字 + 搜索 tab 下回退绝对路径，因为虚拟目录里同名是常态）。`handleCtxSelect` 加 `case "run-as-admin"` → 新增的 `doRunAsAdmin()`：**只作用于右键那一行，不作用于整个多选集合**（没人想「把这三个程序都以管理员身份跑一遍」）；成功**不弹 toast**（提权窗口起来本身就是反馈，toast 反而会在用户应对 UAC 时挂在界面上）；失败按是否含 `已取消` 分流成 info / error toast。
  - 验证：`cargo fmt --check` + `cargo check` 均 exit 0（走 `scripts/cargo-check.sh`，它手动 export 了 BuildTools 的 MSVC/SDK 路径——`dev.bat`/`dev.sh` 的探测列表漏了 BuildTools，别指望它们）；`vite build` exit 0，主 bundle 241.56 kB（改动前 240.82 kB）。新增 4 个 `#[cfg(windows)]` 单元测试覆盖判定逻辑（伪造 MZ 但无 PE 签名 / `e_lfanew` 越界 / 全注释脚本与 UTF-16 BOM 脚本 / msi·msp·lnk 路由与大小写不敏感 / 目录与 txt 不放行）。⚠️ 本机 WorkBuddy 沙箱把 `reg.exe` 列进了程序黑名单，导致走 `vcvars64.bat` 的那条 `cargo check` 路径必然失败（cc 编译链要 reg），**这是环境限制不是代码问题**；纯 Rust 部分另用 `rustc --test` 单独编译实跑过，4 passed。待用户双击 `dev.bat` 实测：右键 `.exe`/`.bat`/`.ps1`/`.msi`/`.lnk` 有该项、`.txt`/目录没有，改名成 `.exe` 的文本文件也没有，拒绝 UAC 只提示取消。
