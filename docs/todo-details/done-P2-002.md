- [x] **收敛：`expand_env_vars` 遇未闭合 `%` 会把路径剩余部分整段丢掉** — `lib.rs:322-349`。else 分支 `i = j + 1` 而 `j == len`，于是 `i == len+1`，中间的 `"USERPROF"` **从未被 push**。地址栏手输 `%USERPROF`（漏打一个 `%`）→ 变成 `"%"` → 后面所有字符被吞掉 → 用户看到「路径不存在」而不是「你少打了个百分号」。`%%` 则匹配到空变量名、静默清空。
  **已修（2026-10-14）**。缺陷先用 Python 精确模拟**实测确认**（不是照着注释推因果 —— 项目里已经有过一次「注释里的因果断言同样会错」的记录）：`%USERPROF` → `%`、`a%b` → `a%`、`%%` → `''`。
  - **`else` 改 `i += 1`**：没有收尾 `%` 就不构成占位符，跑到末尾那段是普通文本，只前进一个字符。价值在于**失败模式可见** —— 宁可让用户看见自己打错的东西，也不要悄悄换一条路径。
  - **`%%` 判为字面量**：空变量名不是占位符，展开成空串会让路径凭空消失而屏幕无任何线索。本项目**不定义转义语法** —— 凭空让 `%%` 在这里表示别的东西比保留它更糟。
  - **未知变量仍展开为空**（保持既有行为，非本次范围），已用测试钉住，免得日后有人「顺手改成回显」`%NOSUCH%`，把本就不存在的路径交给后端解析。
  - **环境变量查找参数注入**：`expand_env_vars_with(input, lookup)` + 薄 wrapper `expand_env_vars`。测试不读也不写真实进程环境（跨机器不稳定，且 `set_var` 在并行测试 runner 里是数据竞争）。
  - **测试 7 例**：正常展开、未闭合保留剩余、空变量名字面量、未知变量、多字节文本（`Vec<char>` 上的扫描若按字节算会截断多字节字符并在切片处 panic）、生产入口 wrapper。
  - 🚨 **变异测试抓到一条「测试测不出自己没测的东西」**：把 `expand_env_vars` 改成硬编码返回值，**75 个测试全绿** —— 因为那条 wrapper 测试自己 `set_var` 设了值，坏实现压根不看环境也照样答对。纯行为断言对「实现不再委派」是瞎的，补 `include_str!` **静态断言**才抓住 → FAILED。needle 用 `concat!` 在运行时拼（否则判据文本被自己读回来、自己判自己通过），并**实测负对照**（needle 故意写错 → 确实 FAILED）。另外两个变异（`i = j + 1` 复现原缺陷、删掉空名保护）分别被 2 例 / 1 例抓住。
  - `cargo fmt --check` exit 0、`cargo test --lib` **75 passed 0 failed**。**待用户双击 `dev.bat` 实测**：地址栏手输 `%USERPROFILE%`（应展开）、手输 `%USERPROF`（应看到原样文本 + 路径不存在，而非静默变短）、手输 `%%`。
