- [x] **修复：行 `:key` 用 `entry.name`，虚拟目录必然撞键** — `FileList.vue:100-101`。项目硬约束要求虚拟目录用 `entry.path`。搜索结果里跨目录重名是常态，`:key` 重复时 Vue 的 keyed diff 那张 `key -> 下标` 的 map 被后者覆盖，节点复用**整体错位一格**：列表 `[A,B,C,D]` 里 D 挪到开头变成 `[D,A,B,C]` 后，第 1 行的位置上是 D、行内状态却自称 A。落到本项目 = 搜索结果页一切「按行缓存」的东西（已算的目录大小、已裁的缩略图、内联改名状态）都贴在错误的行上。
  **已修**：判据抽成 `src/paths.js` 的 `entryKey()`（与 `entryPath` 同处；组件与测试共用一份，不复制进测试脚本）。测试两条：`entry-key-check.mjs` 管表达式本身（唯一性 + 静态断言模板确实调它，含三种变异验证）；`row-key-identity-check.mjs` 用**真实 @vue/runtime-core + 无 DOM test renderer** 跑真实 keyed diff，8 种增删/重排场景下断言「该位置的磁盘条目 == 该位置组件自称的身份」，修复前 7 个场景串台、修复后零串台。
  ⚠️ **本条原先写的后果是错的，已更正**：原描述称「内联改名输入框会挂到错误的文件上，回车就把用户没输入的名字写到没选中的文件上」。实测推翻 —— 输入框位置只由 `renamingIndex` 这个**下标**决定，正确搬运下标后两种 key 表现完全一致；真正出错位的场景（删行/插入时 remap 没做）是 TODO 244 那条，与 key 无关。
